# D references

Offline reference material for the in-tree D backend (`src/d/`). The backend
implements the D ABI name-mangling grammar and prints the `c++filt -s dlang`
spelling. `refs/` is excluded from the published crate; this note records
provenance, the pinned toolchain, the extraction commands and the measured
corpus breakdown.

## Upstream references

### D ABI specification

- URL: <https://dlang.org/spec/abi.html> (section "Name Mangling")
- Site source pinned at `dlang/dlang.org` commit
  `da34ce20bd0ce4e045335c299ac613c04f983f23` (2026-11-09).
- Retrieved: 2026-11-23.
- License: Boost Software License 1.0 (the dlang.org `LICENSE.txt`).
- Not vendored: the grammar is small and the page is generated; the link above
  is the reference. The grammar used by the parser is the `MangledName`,
  `QualifiedName`, `SymbolFunctionName`, `TemplateInstanceName`, `Type` and
  `Value` grammar from that page.

The binutils 2.44 oracle implements an older slice of the same grammar. Where
the specification and `c++filt` differ, the corpus records the difference
instead of treating the oracle as authoritative: for example, binutils does not
print `I` (`TypeIdent`), `_DThn16_` template wrappers, or `M` followed by a
back-referenced type modifier. The parser follows the oracle for `TypeTuple`
(`B Number Types`) and accepts `V` (Pascal) as a calling convention; the
specification page spells tuple as `B Parameters Z`.

### LDC and Phobos

- Upstream: <https://github.com/ldc-developers/ldc> and
  <https://github.com/dlang/phobos>.
- LDC 1.40.0, based on DMD 2.110.0 and LLVM 19.1.7.
- Debian package `ldc` version `1:1.40.0-5` (`x86_64-linux-gnu`).
- Phobos 2.110.0 from Debian package `libphobos2-ldc-shared110` version
  `1:1.40.0-5`, shared library
  `/usr/lib/x86_64-linux-gnu/libphobos2-ldc-shared.so.110.0`.
- Retrieved: 2026-11-23 from the Debian packages listed above.
- License: Boost Software License 1.0 (Phobos and druntime).
- Only symbol names and expected text are vendored; no compiler, library or
  object file is stored in `refs/d/`.

### GNU binutils `c++filt`

- Upstream: <https://sourceware.org/binutils/>.
- GNU c++filt (GNU Binutils for Debian) 2.44, Debian package `binutils`
  version `2.44-3`, retrieved 2026-11-23.
- Used as a generation-time oracle only; the backend never invokes it at
  runtime. The libiberty D demangler is LGPL-2.1-or-later. No binutils source
  is vendored or copied; the corpus stores generated demangled text.

## Extraction

The extraction commands are also in `refs/d/extract-d-symbols.sh` and the
classification rules are in `refs/d/classify-corpus.py`.

```sh
# libphobos shared-library symbols (defined `_D` names only)
nm -D --defined-only /usr/lib/x86_64-linux-gnu/libphobos2-ldc-shared.so.110.0 \
  | awk '{print $3}' | grep '^_D' | sort -u > libphobos.syms

# expected text from the pinned oracle
c++filt -s dlang < libphobos.syms > libphobos.expected

# LDC probe object (source is generated by extract-d-symbols.sh)
ldc2 -c -g -O0 app.d -of=app.o
nm app.o | awk '{print $NF}' | grep '^_D' | sort -u > app.syms
c++filt -s dlang < app.syms > app.expected
```

`classify-corpus.py` splits each pair into:

- **exact** — `c++filt` output differs from the input, so the oracle produced a
  demangling. This is the only class counted as coverage.
- **oracle-gap** — `c++filt` echoed the input. Echoes are never counted as
  exact, even if the input is a valid D symbol that the in-tree parser can
  handle.
- **documented-unsupported** — hand-authored valid-looking productions that
  this first slice deliberately rejects. They are listed in `unsupported.tsv`
  and the corpus test requires rejection.
- **negative** — malformed, truncated or ambiguous inputs. They are listed in
  `negative.tsv` and the corpus test requires rejection.

No `c++filt` `<...>` placeholder output was observed for this corpus. The `<`
characters in the expected text are string-literal payloads such as
`safeOp!("<")`, not placeholders.

## Corpus files

| File | Rows | Meaning |
|------|-----:|---------|
| `d/hand.tsv` | 173 | Hand-written spec cases; all exact |
| `d/ldc-1.40-app.tsv` | 36 | Symbols from the LDC 1.40 probe object; all exact |
| `d/libphobos-2.110.0.tsv` | 10,257 | Defined `_D` symbols from the pinned libphobos; all exact |
| `d/oracle-gap.tsv` | 461 | libphobos symbols that `c++filt` echoed |
| `d/negative.tsv` | 24 | Malformed/truncated/ambiguous forms; must be rejected |
| `d/unsupported.tsv` | 3 | Documented first-slice rejections |

Every exact row is `symbol<TAB>expected<TAB>comma-separated categories`. The
categories are multi-label; a symbol may be both `template` and `function`.

## Measured category breakdown

Counts over the 10,466 exact rows (`hand.tsv` + `ldc-1.40-app.tsv` +
`libphobos-2.110.0.tsv`):

| Category | Rows |
|----------|-----:|
| `qualified` | 10,051 |
| `function` | 8,844 |
| `template` | 6,740 |
| `array` | 3,921 |
| `constant` | 3,099 |
| `runtime-special` | 1,509 |
| `class` | 687 |
| `typeinfo` | 432 |
| `delegate` | 167 |
| `local` | 98 |

`local` counts nested function names (`outer(int).inner(int)`) and the `__S`
fake-parent hand cases; the pinned shared-library symbols contain no `__S`.
`typeinfo` counts `TypeInfo_*` symbols, which the ABI encodes as ordinary
identifiers and which the oracle prints as `initializer for TypeInfo_…`.

## Gate result

- Hand corpus: 173/173 exact.
- Generated corpus: 10,293/10,293 exact (36 LDC + 10,257 libphobos).
- Wrong output: 0.
- Oracle gaps: 461, all `c++filt` echoes; the in-tree parser rejects all of
  them, so none is counted as coverage.
- Documented unsupported: 3 hand-authored productions.
- Negative forms: 24, all rejected.

The corpus test is `tests/d_corpus.rs`; it is gated on the `d` feature and
skips when `refs/d/` is absent.

## Refresh procedure

1. Update the LDC/Phobos package and `c++filt` versions above.
2. Re-run `refs/d/extract-d-symbols.sh` and `refs/d/classify-corpus.py`.
3. Re-run `cargo test --no-default-features --features d --test d_corpus`.
4. Raise the category counts in this note if coverage improves; never lower
   the gate or reclassify a wrong row as exact.
